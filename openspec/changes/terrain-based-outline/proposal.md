## Why

SquawkMap3D already shows the feeder's *actual* observed reception envelope (`actual-range-outline-layer`, `outline.json`), but that only reflects what has already been received — it says nothing about where the antenna's line of sight is blocked by terrain, or how far it *should* be able to see an aircraft at a given altitude if signal were the only limit. [HeyWhatsThat](https://www.heywhatsthat.com/) computes exactly that from a digital elevation model, given a "panorama" generated for a site: a per-bearing horizon profile, and — via its `upintheair.json` API — a ready-made set of maximum theoretical detection-range rings, one per requested altitude. `wiedehopf/tar1090` (`drawUpintheair()`, `html/script.js`) and, downstream of it, `dirkhh/adsb-feeder-image`'s own HeyWhatsThat integration (`utils/multioutline.py`'s `create_heywhatsthat()`/`_get_heywhatsthat()`, consuming `upintheair.json` files this same way) both already treat this as a distinct, terrain-derived layer alongside the actual-observation outline — this change adds SquawkMap3D's own equivalent.

## What Changes

- Add a **Terrain-Based Outline** layer: given a HeyWhatsThat panorama ID (accepted either as the bare ID, e.g. `CG4B3P7M`, or a full panorama URL, e.g. `https://www.heywhatsthat.com/?view=CG4B3P7M`, per the acceptance criteria's example), fetches `https://www.heywhatsthat.com/api/upintheair.json?id=<ID>&refraction=0.25&alts=<meters,...>` directly from the browser — this endpoint returns `Access-Control-Allow-Origin: *` (confirmed live), so, unlike `outline.json`, no same-origin proxy is needed.
- Parses the response's `rings` array (`[{ alt: <meters>, points: [[lat, lon], ...] }, ...]`, one ring per requested altitude, an open — not closed — ring of one point per degree of azimuth) into a GeoJSON `FeatureCollection` of closed `LineString` features, one per altitude, each carrying its altitude (feet) as a feature property — the same reverse-engineered response shape `drawUpintheair()` and `multioutline.py` both already consume, and the same "close the ring by repeating the first point" convention `rangeOutline.ts`/tar1090's own `drawOutlineJson()` already use for `outline.json`.
- Renders those rings as **unfilled stroked outlines** (a deliberate difference from `actual-range-outline-layer`'s solid fill — this layer's own acceptance criterion calls for "a series of outlines," and a solid fill would make an outer, larger-altitude ring's interior opaquely cover every smaller ring nested inside it), one line per requested altitude, colored along this app's existing `ALTITUDE_COLOR_STOPS` gradient (`aircraftIcons.ts`, the same ramp already used for altitude-colored aircraft icons/tracks) so each ring's color ties back to a legible altitude, without inventing a second color convention.
- The whole set of rings is a single toggle, named "terrain-based outline" per the acceptance criteria, in the existing layer-toggle row (`MapView.tsx`'s `.controls` list), following the established visibility ref/state pair pattern every other layer already uses, and survives theme/pilot-mode style swaps.
- Configured via a new build-time env var (`NEXT_PUBLIC_HEYWHATSTHAT_PANORAMA_ID`), matching the existing `NEXT_PUBLIC_FEEDER_URL`/`NEXT_PUBLIC_OPENAIP_API_KEY` "optional, deployer-configured, degrade to empty when unset" convention — no in-app settings UI exists for any other layer, so this doesn't introduce one either.

## Capabilities

### New Capabilities
- `terrain-based-outline-layer`: a HeyWhatsThat-panorama-derived set of per-altitude theoretical line-of-sight range outlines, rendered as a toggleable set of stroked (unfilled) polygon outlines colored by altitude.

### Modified Capabilities
(none — additive layer; existing `actual-range-outline-layer`, `map-view`, and every other capability are unaffected)

## Impact

- `components/map/terrainOutline.ts` (new): `fetchTerrainOutline(): Promise<GeoJSON.FeatureCollection<LineString, { altitudeFt: number }>>` — builds the HeyWhatsThat `upintheair.json` URL from the configured panorama ID and `TERRAIN_OUTLINE_ALTITUDES_FT`, fetches it directly (no proxy), parses `rings`, converts each ring's `[lat, lon]` points to closed GeoJSON `[lon, lat]` `LineString`s tagged with `altitudeFt`, and returns an empty `FeatureCollection` (never throws) when no panorama ID is configured, the request fails, the response body is empty/unparseable (HeyWhatsThat returns HTTP 200 with an empty body for an unknown/invalid panorama ID — confirmed live), or `rings` is missing/empty — mirrors `rangeOutline.ts`/`tfr.ts`'s "fail to empty, never error" convention.
- `components/map/constants.ts`: `getHeywhatsthatPanoramaId(): string | undefined` (reads `NEXT_PUBLIC_HEYWHATSTHAT_PANORAMA_ID`, extracting the `view` query param if a full panorama URL was pasted in rather than a bare ID), `HEYWHATSTHAT_UPINTHEAIR_API_URL`, `HEYWHATSTHAT_REFRACTION` (`"0.25"`, matching tar1090's own `getupintheair.sh`/`drawUpintheair()` doc comment default), `TERRAIN_OUTLINE_ALTITUDES_FT` (a fixed list of altitudes in feet, converted to meters when building the request URL).
- `components/map/layers.ts`: `TERRAIN_OUTLINE_SOURCE_ID`/`TERRAIN_OUTLINE_LINE_LAYER_ID` (added to `addCustomLayers`/`CustomLayerVisibility`/`CUSTOM_LAYER_IDS`, same pattern as the TFR/SUA/actual-range-outline layers), a `line-color` paint expression interpolating along `ALTITUDE_COLOR_STOPS` by each feature's `altitudeFt` property, `setTerrainOutlineVisibility`, `refreshTerrainOutline`.
- `components/map/MapView.tsx`: new visibility ref/state pair, a "Hide/Show terrain-based outline" toggle button, and a fetch-once-on-mount-and-on-style-reload wiring (no polling interval — unlike `outline.json`/TFR/SUA, a HeyWhatsThat panorama's terrain data doesn't change between reloads, so there's nothing to periodically refetch).
- No breaking changes to any existing layer or capability; no new npm dependencies; no nginx/proxy changes (HeyWhatsThat's API already serves permissive CORS headers, confirmed live).
