## Why

`PlaneCard` (`components/map/overlay/PlaneCard.tsx`) was built to be a field-for-field mirror of adsb.win's own real dashboard aircraft card, but its CSS has drifted from — and in some places never fully implemented — that reference. Re-fetching the reference stylesheet (`https://adsb.win/assets/tailwind-1909ad77.css`, superseding the `tailwind-255296c3.css` snapshot `PlaneCard.module.css`'s own comments still cite) and diffing it against this codebase surfaces concrete, fixable bugs: the adsb.win-tier ("material tier": carbon/alloy/titanium/iridium/plasma/quantum — the same six-entry ladder `tierProgress.ts` already codes) badge and its XP progress bar render with flat, non-tier-colored styling instead of each tier's own real accent colors, and the card body is missing that same reference's per-tier decorative surface treatment (background swap plus animated shimmer/pulse/drift/aurora overlays) entirely; the `mythic`/`apex` rarity-tier frame is missing its reference `rarity-sheen` animated highlight sweep even though its static gradient is already correct; the badge row's gap and overflow handling don't match the reference's literal values; and the JS-measured shrink-to-fit transform applied when a card's own content doesn't fit its box scales only the vertical axis (`scaleY`), squashing/distorting every child element's proportions instead of preserving them — a real visual bug, and also an inconsistency with the rest of the overlay's own outer shrink-to-fit mechanism (`AircraftOverlay.module.css`'s grid-level ResizeObserver), which already scales uniformly.

## What Changes

- Add the real six-entry material-tier ("carbon"/"alloy"/"titanium"/"iridium"/"plasma"/"quantum") accent-color system to `PlaneCard.module.css`, sourced byte-for-byte from `tailwind-1909ad77.css`'s `.aircraft-tier`/`.aircraft-tier--*`/`.aircraft-card-badges--*`/`.aircraft-tier__badge`/`.aircraft-tier__progress` rules, driven by a new `data-material-tier` attribute (set from `cardStats.attributes.tier`, normalized the same way `tierProgress.ts` already normalizes it) on the card. Recolors `.tierBadge` and the XP progress bar (`.progressFill`/`.progressFillMax`) to that tier's own colors instead of the current flat/neutral styling — and fixes the progress bar's current cross-wired bug where it's colored from `--rarity-color`/`--rarity-highlight` (the *rarity* tier, a different axis) instead of the material tier's own color.
- Add each material tier's real decorative surface treatment: a per-tier background gradient override on the card body (replacing today's single fixed gradient, which is actually just the `carbon` tier's own background applied unconditionally to every tier) plus `:before`/`:after` pseudo-element overlays and the reference's real keyframe animations (`iridium-shimmer`, `plasma-drift`, `plasma-pulse`, `quantum-aurora`, `quantum-rim`), with `carbon`/`alloy`/`titanium` getting their own subtler static-pattern treatments per the reference. Degrades to today's flat gradient (no `data-material-tier`) when `cardStats` isn't `"ok"` or the reported tier name isn't one `tierProgress.ts`'s table recognizes.
- Add the reference's `rarity-sheen` animated highlight sweep to the existing `mythic`/`apex` rarity-tier frame overrides (the static gradient is already correct; only the animation is missing).
- Fix `.badgeRow`'s gap from an invented `8px` to the reference's real `0.35rem`, and add the reference's `max-width: calc(100% - 2rem)` plus per-badge `text-overflow: ellipsis`/`white-space: nowrap`/`overflow: hidden` so a long badge label truncates instead of overflowing the card's rounded corners on narrow cards.
- Replace `PlaneCard.tsx`'s measured shrink-to-fit `transform: scaleY(scale)` with a uniform `transform: scale(scale)`, matching the aspect-ratio-preserving technique the overlay's own outer grid-level ResizeObserver scale (`AircraftOverlay.tsx`) already uses, so badges, text, and the aircraft silhouette shrink proportionally instead of only being compressed vertically. This directly addresses "keep scale consistent with aspect ratio regardless of scale" and "allow fonts and image to shrink to match vertical height" — under the current `scaleY`-only approach, fonts/badges/the icon get vertically squashed rather than uniformly shrunk.
- Re-verify and correct every literal color/gradient/box-shadow/spacing value already present in `PlaneCard.module.css` against `tailwind-1909ad77.css` (this change's fetched source of truth), and update the file's header comment to cite that hash instead of the stale `tailwind-255296c3.css` one.
- Manually verify the resulting card in a running browser session against the live reference (`https://adsb.win/dashboard?tab=aircraft`, an authenticated page this change's implementer/reviewer needs their own adsb.win login to view) across multiple rarity tiers and, if a real or mocked `"ok"` `cardStats` result across multiple material tiers is available, across multiple material tiers too.

## Capabilities

### Modified Capabilities
- `aircraft-info-overlay`: `PlaneCard`'s "shows optional fleet-wide stats" requirement gains real per-material-tier accent styling (badge + progress bar + card-body decoration) instead of flat/neutral styling; a new requirement is added specifying that `PlaneCard`'s own measured shrink-to-fit preserves the proportions (aspect ratio) of its content rather than distorting them.

## Impact

- `components/map/overlay/PlaneCard.module.css`: adds `data-material-tier` variable blocks (`--tier-color`/`--tier-highlight`/`--tier-glow`) and their six per-tier `:before`/`:after` decorative overrides plus `@keyframes iridium-shimmer/plasma-drift/plasma-pulse/quantum-aurora/quantum-rim`; adds `@keyframes rarity-sheen` and wires it to the existing `mythic`/`apex` selectors; recolors `.tierBadge`/`.progressFill`/`.progressFillMax` off the new tier variables; fixes `.badgeRow`'s gap and adds `max-width`/text-overflow handling; updates the file's header source-of-truth comment.
- `components/map/overlay/PlaneCard.tsx`: sets `data-material-tier` from `cardStats.attributes.tier` (normalized like `tierProgress.ts`), omitted/absent when `cardStats` isn't `"ok"` or the tier is unrecognized; changes the shrink-to-fit `style` prop from `scaleY(scale)` to `scale(scale)`.
- No changes to `aircraftModelCard.ts`, `tierProgress.ts`, or any data-fetching/API contract — this change is presentation-only.
- No changes to any other overlay component (`RecordPanelHero`, `TelemetryMarquee`, `FlightInfoPane`) or to the `aircraft-rarity`/`adsb-win-aircraft-stats` capabilities' documented behavior beyond the styling noted above.
