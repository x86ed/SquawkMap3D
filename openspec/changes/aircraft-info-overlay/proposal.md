## Why

Clicking an aircraft on the map currently does nothing — `AIRCRAFT_ICON_LAYER_ID`'s deck.gl `IconLayer` is `pickable: false`, and there is no selection state, no way to identify a specific aircraft's registration/type/operator, and no way to keep the map centered on one aircraft while it moves. The airports layer already proved the "click a map feature, see a details surface" pattern (`airport-details-popup`); aircraft need the equivalent, but richer — identity, live telemetry, and flight-progress context — surfaced as a persistent bottom drawer rather than a transient popup, since aircraft move and a popup anchored to a moving point is awkward to read.

## What Changes

- Add click-to-select on the aircraft icon layer: clicking an aircraft's icon selects it (deselecting any previously-selected aircraft); clicking empty map area, clicking the selected aircraft again, or pressing Escape deselects it.
- Add a first-of-its-kind rarity-tier system for this codebase (`components/map/aircraftRarity.ts`) — no existing rarity/tier logic was found to reuse (confirmed: no `rarity`/`tier` grep hits anywhere outside this change). **Amended:** this now reproduces adsb.win's own real, verified 9-value tier taxonomy — `unidentified`, `standard`, `prime`, `remarkable`, `exceptional`, `epic`, `legendary`, `mythic`, `apex` — rather than an invented 5-tier approximation. `unidentified` is a distinct "no rarity classification exists for this type" case (an aircraft with no `typeDesignator`, or one with no matching row in the vendored `aircraftRareness.json` snapshot), not a bucket on the numeric scale. The other 8 named tiers are bucketed from the same vendored per-aircraft-type `rareness` dataset (`components/map/data/aircraftRareness.json`, trimmed from the `taildragger` sibling project — see design.md Decision 5) via fixed, data-derived **octile** thresholds (7 cutpoints for 8 equal-population buckets). Each of the 8 named tiers maps to adsb.win's own exact `{ color, highlight, glow }` CSS custom-property triple (verified directly from `https://adsb.win/assets/tailwind-255296c3.css`, re-confirmed byte-for-byte during this amendment), including `mythic`'s conic-gradient and `apex`'s pearlescent linear-gradient frame overrides; `unidentified` uses the base rule's own defaults. This is a data-backed decision for *which* aircraft land in which numeric bucket (still `taildragger`'s dataset, not adsb.win's undisclosed algorithm) combined with now-verified-exact tier names/colors (no longer hand-approximated).
- Render a glow highlight around the selected aircraft's icon, colored by its computed rarity tier, on the existing aircraft deck.gl overlay; the glow tracks the aircraft's live position and clears on deselect or when the aircraft drops out of the feed.
- Add a "Follow selected aircraft" toggle control (default **on**, alongside the existing layer-toggle buttons) that, while enabled, locks the camera to a newly-selected aircraft immediately on selection and keeps it centered on every subsequent aircraft-feed refresh — framed as the aircraft staying pinned at a fixed on-screen position while the map pans underneath it, not the reverse (see design.md Decision 13). The lock is broken only by deselecting the aircraft (click elsewhere, re-click, or Escape); manual map panning/dragging while locked does not break it.
- Extend `Aircraft`/`normalize()` in `components/map/aircraft.ts` to also map readsb's `r` (registration), `desc` (manufacturer/model description string), `ownOp` (operator name), `year`, and `seen` (seconds since last message) fields — same optional/`undefined`-when-omitted treatment already established for `t` (only populated when the feeder loads a tar1090-db `aircraft.csv.gz`).
- Extend the session-local track buffer (`TrackPoint` in `aircraft.ts`) to also retain `groundSpeed` per point, so a selected aircraft's recent altitude/speed history is available for a sparkline without a new parallel data structure.
- Add a full-width bottom drawer (`AircraftOverlay`, new `components/map/overlay/` directory) that opens when an aircraft is selected and closes on deselect, built from **four separate components** (own file each, each independently testable/reusable):
  - `PlaneCard`: identity card (registration, manufacturer/model, operator, rarity tier badge/accent), built on adsb.win's real two-layer gradient-border-frame technique (see design.md Decision 5) and forward-plumbed (but never fabricated) to render real per-aircraft-type fleet stats (unique registrations, flights captured, observed flight time, highest altitude, XP + progress-to-next-tier) whenever a future data source populates them — see design.md's new stat-plumbing decision.
  - `RecordPanelHero`: registration/callsign/ICAO hex + manufacturer/model/operator/age spec grid, with portrait/landscape reflow driven by the panel's own measured aspect ratio (`ResizeObserver`), not viewport size.
  - `TelemetryMarquee`: scrolling monospace ticker of live telemetry (altitude, ground speed, heading, vertical rate with trend, squawk, distance from the feeder/user site, seconds since last message), pausing on hover/focus.
  - `FlightInfoPane`: dual sparkline (altitude + ground speed, independently normalized) built from the extended track buffer, covering only this change's real, in-scope data.
- Source flight route (origin/destination) and timeline data from the feeder's own tar1090 install, which already surfaces route lookups in its own UI: proxy tar1090's route-lookup endpoint through this app's existing nginx sidecar (`scripts/squawkmap3d.nginx.conf`), mirroring the already-established `receiver.json`/`outline.json` proxy pattern (see design.md Decision 12), rather than calling a third-party API. The exact endpoint path/response shape must be confirmed against a running feeder before implementation (a blocking, early task scoped to this piece only — see tasks.md). `FlightInfoPane`'s route/progress-bar and Timeline elements render the real route when tar1090 resolves one for the aircraft's callsign, and an explicit "no route data available" empty state when it does not (a legitimate per-aircraft fallback, e.g. general aviation with no filed route — not the default-for-everything behavior).

## Capabilities

### New Capabilities
- `aircraft-rarity`: computes a rarity value + tier + accent color for an aircraft from its type designator, looked up against a vendored per-type rareness dataset snapshot; consumed by both the map glow highlight and the drawer's `PlaneCard`/`RecordPanelHero`.
- `aircraft-info-overlay`: the bottom-drawer UX (open/close/Escape/scrim/responsive stacking) and its four constituent components (`PlaneCard`, `RecordPanelHero`, `TelemetryMarquee`, `FlightInfoPane`).

### Modified Capabilities
- `aircraft-tracks-layer`: aircraft icons become clickable/selectable (`pickable: true`), the selected aircraft renders a rarity-colored glow highlight, and a "Follow selected aircraft" toggle control is added.

## Impact

- `components/map/aircraft.ts`: extend `Aircraft`/`RawAircraftJson`/`normalize()` with `registration`, `manufacturerModel`, `operator`, `year`, `secondsSinceLastMessage`; extend `TrackPoint`/`updateTracks()` with `groundSpeed`.
- `components/map/aircraftLayer.ts`: `pickable: true` + `onClick` on the `IconLayer`; new glow-highlight layer (likely a `ScatterplotLayer`, mirroring `radarSweep.ts`'s existing use of that layer type) keyed off selected-aircraft state passed into `buildAircraftLayers`.
- New `components/map/aircraftRarity.ts`: `computeRarityValue(aircraft: Aircraft): number` + `computeRarityTier(aircraft: Aircraft): RarityTier` + `RARITY_TIER_COLORS`/`RARITY_TIER_THRESHOLDS`, reading from a new vendored data file.
- New `components/map/data/aircraftRareness.json`: a trimmed (`id`/`rareness` only), build-time-vendored snapshot of the `taildragger` sibling project's per-aircraft-type rareness dataset (~1679 entries, ~56KB), generated by a new one-time/manually-re-run script (e.g. `scripts/generate-aircraft-rareness.mjs`) — not fetched at runtime, not part of CI.
- New `components/map/flightRoute.ts`: `getFlightRoute(callsign: string): Promise<FlightRoute | null>`, mirroring `feederLocation.ts`'s `getFeederLocation()` contract (always resolves, never rejects), fetching the proxied tar1090 route endpoint.
- `scripts/squawkmap3d.nginx.conf`: new `location = /data/<route-endpoint-path>` proxy rule to the ultrafeeder container, matching the existing `receiver.json`/`outline.json` blocks, once the exact tar1090 route endpoint is confirmed (see tasks.md's blocking discovery task).
- `components/map/MapView.tsx`: selection state (`selectedAircraftHex`/ref), `onClick` wiring on the aircraft `IconLayer`, map-click/Escape-key deselect handling, "Follow selected aircraft" toggle state + immediate `easeTo` on selection + `easeTo` recentering on each aircraft-feed poll while locked, mounting `AircraftOverlay` with the selected aircraft's derived view-model (including its resolved route).
- New `components/map/overlay/` directory: `AircraftOverlay.tsx` (+ `.module.css`), `PlaneCard.tsx`, `RecordPanelHero.tsx`, `TelemetryMarquee.tsx`, `FlightInfoPane.tsx` (each + its own `.module.css`, following the existing `MapView.module.css` CSS-Modules convention — this repo has no Tailwind/CSS-in-JS dependency), plus `selectedAircraftInfo.ts` for the shared view-model builder.
- `components/map/constants.ts`: any new tunable constants (glow radius/opacity, marquee scroll speed, follow-toggle default).
- No new npm dependencies: distance-from-site (`DIST`) and route ETA computation reuse the already-installed `@turf/turf` (precedent: `radarSweep.ts`'s `turf.bearing`/`turf.distance` usage, and the already-bundled `/data/airports.geojson`); the marquee's monospace font reuses the already-loaded `--font-geist-mono` (no new font dependency, unlike the mockup's literal JetBrains Mono).
