## 1. Solar position math

- [x] 1.1 In `components/map/terminator.ts`, implement pure functions for: Julian day from a `Date`, Greenwich Mean Sidereal Time, the sun's ecliptic longitude, ecliptic obliquity, and the sun's equatorial position (right ascension + declination) — standard solar-position formulas, no dependency.
- [x] 1.2 Implement `terminatorLatitudeAtLongitude(lng, sunPosition, gst, elevationDeg): number | null` solving `sin(elevationDeg) = sin(lat)sin(δ) + cos(lat)cos(δ)cos(H)` for latitude given the hour angle `H` at that longitude; return `null` where no real solution exists (that longitude is entirely inside/outside this elevation band at every latitude — i.e. polar day/night).
- [x] 1.3 Add a few sanity-check unit tests (`node --test`, matching the project's existing `test/` convention) for the pure math: subsolar declination ≈ Earth's axial tilt (~23.44°) at a known solstice date, ≈ 0° at a known equinox date.

## 6. Dark-theme screen blend (WebGL)

Added after 1-5 above were already verified working, per explicit user request for a true blend mode in dark theme (a flat alpha-blended fill, even after the region fix in 5.4's round 3, still just washes the map toward one flat tint instead of brightening it while preserving underlying detail). See design.md's addendum for the full rationale/alternatives considered.

- [x] 6.1 Add `earcut` as an explicit dependency (`npm install earcut`) — already present transitively via `maplibre-gl`/`@turf/turf` (which use it internally for the same polygon-triangulation problem), pinned explicitly since this is now a direct, load-bearing usage.
- [x] 6.2 In new `components/map/terminatorGL.ts`, implement `TerminatorScreenBlendLayer`, a MapLibre `CustomLayerInterface`: compiles a minimal GLSL ES 3.00 vertex/fragment shader pair, triangulates each band polygon with `earcut` and projects vertices to Mercator world space via `MercatorCoordinate.fromLngLat` in `updateBands` (once per data refresh, not per frame), and in `render` sets `gl.blendFunc(gl.ONE_MINUS_DST_COLOR, gl.ONE)` (the fixed-function-blending trick for a true "screen" blend) before drawing each band, restoring MapLibre's documented default blend func afterward. Exposes `updateBands(bands)` and `setVisible(visible)` (the latter calling `map.triggerRepaint()` for an immediate visual update, since custom layers have no `layout.visibility` property).
- [x] 6.3 In `components/map/terminator.ts`, branch `addTerminatorLayers`/`refreshTerminator`/`setTerminatorVisibility` on `theme`: light theme keeps the original `fill`-layer/GeoJSON-source path unchanged; dark theme creates/reuses a module-level `TerminatorScreenBlendLayer` instance instead, calling `updateBands`/`setVisible` on it. Removed the now-unused `TERMINATOR_REGION_FOR_THEME`/per-theme `BAND_FILL_COLOR`/`BAND_FILL_OPACITY` records (light theme's are now plain constants; dark theme's color/opacity live in `terminatorGL.ts` instead).
- [x] 6.4 Add `TERMINATOR_GL_LAYER_ID` to the exported `TERMINATOR_LAYER_IDS` list so `layers.ts`'s pilot-mode exemption (`CUSTOM_LAYER_IDS`) still covers it.
- [x] 6.5 Manually verify: no WebGL/console errors after load, theme toggle, and terminator toggle. Verified via real-Chromium automation with console-error capture (empty) across a load → toggle-off → toggle-on → theme-swap-to-light → theme-swap-back-to-dark sequence; `map.getLayer("day-night-terminator-gl")` confirmed present before and after the swap round-trip.
- [x] 6.6 Manually verify the screen-blended dark-theme overlay visibly preserves underlying map detail (coastlines, basemap texture) through the brightened day region, rather than washing it to a flat tint. Confirmed via screenshot comparison against the prior alpha-blended version.
- [x] 6.7 Tune `BAND_TINT` in `terminatorGL.ts` for perceptibility: the initial value (`[0.16, 0.18, 0.22]`) read as barely noticeable per direct user feedback. A thumbnail-scale screenshot comparison after doubling it looked inconclusive, so verified objectively instead — decoded a real screenshot's pixels (2D canvas `getImageData`, not raw WebGL `readPixels`, which returns all-zero for MapLibre's canvas without `preserveDrawingBuffer`) and measured brightness across a horizontal strip: background ≈28/255, brightened core ≈154/255, a ~126-point swing. Landed on `[0.32, 0.36, 0.42]`.
