## Why

`PlaneCard` (`components/map/overlay/PlaneCard.tsx`) currently renders a single-face identity card: a static frame with a header row (type badge, manufacturer, model, silhouette) and a stat region below it, with no flip interaction and no front/back split. The `plens-win/Card` library (https://github.com/plens-win/Card) implements a richer two-face flip-card design — front face (name, rarity/level pills, live 3D wireframe art, XP panel) and back face (identity, stat grid, XP bar) — and is vendored/built locally in the sibling `iconizer` project (`iconizer/3D-modeler/vendor/card/{core,wireframe-three}`, which migrated from its own earlier hand-rolled version to actually consuming this library). This change ports that library's real flip-card markup/CSS/3D-art rendering into `PlaneCard`, replacing the current single-face card, with the adjustments the current sighting flow needs: the back face (this app's existing identity+stats layout) shown by default instead of the front, a click handler that opens the selected aircraft's real adsb.win page, and the front face's 3D art sourced from this app's own vendored `.glb` aircraft models (`public/aircraft-models/`) rather than the library's own live in-app reconstruction (which this app has no equivalent of).

**Revision note**: an earlier version of this change ported from `iconizer`'s superseded hand-rolled card code instead of the real library, which produced two defects caught in review: (1) the tier-colored border/badges stayed static while only inner content flipped, rather than the whole card flipping as one object, and (2) the front face showed the existing flat 2D silhouette instead of a 3D model. Both are corrected below — see design.md's Decisions 2 and 5.

## What Changes

- Replace `PlaneCard`'s single-face DOM/CSS with the two-face flip-card structure ported from `@card/core`'s real `card.css`/`aircraft-card.js` (vendored in `iconizer`): `.aircraftRarityFrame` (perspective + tier CSS variables + sizing only — no border of its own) containing `.cardInner` (the 3D-transformed flip container) containing two complete bordered faces, `.cardFaceFront`/`.cardFaceBack`, each carrying the shared `.cardFace` gradient-border class — so the whole card (border included) flips as one object, not just its inner content.
  - Front face: manufacturer/model header (top-right), rarity + tier pills (top-left), full-bleed 3D wireframe art of the aircraft's vendored `.glb` model (or the flat 2D silhouette when no model is vendored for that type), XP panel — new to this app's `PlaneCard`, ported from the library.
  - Back face: this app's existing identity header, stat grid (unique registrations, flights captured, observed time, highest altitude), XP/tier progress bar, feeder-UUID inline form states, and the rarity/tier badge row — the current `PlaneCard` content, relaid out onto the back face rather than the card's only face.
- **BREAKING (visual/interaction only)**: default orientation is reversed from the `plens-win/Card` original — the back face (stats) shows by default and hovering flips to the front face (identity + 3D art + XP panel), rather than the library's own front-by-default behavior. This default is exposed as a new `showBack` prop on `PlaneCardProps` (`boolean`, default `true`, mirrored via `data-show-back`'s presence — matching the library's own boolean-attribute convention) rather than a hardcoded CSS rule, so any current or future view mounting `PlaneCard` explicitly controls/inherits the back-by-default behavior instead of it being an invisible CSS-only convention; `showBack={true}` is the default and is what every current call site (`AircraftOverlay`) gets without passing anything.
- Card frame's tier-driven gradient border, glow, and `mythic`/`apex` special-tier treatments are preserved unchanged (already standardized between this app and the library; no rarity-tier logic changes) — now applied per-face rather than once on the outer frame (see design.md Decision 2).
- Clicking anywhere on the card (either face, excluding interactive children — the feeder-UUID form's input/button, and any link) SHALL navigate to `https://adsb.win/dashboard/aircraft/{TYPE_DESIGNATOR}` for the selected aircraft's ICAO type designator, in a new tab — the same destination `PlaneCard`'s current click handler already opens (this behavior is preserved from the existing implementation, now applying to both faces rather than only the current single face).
- Front face's art is a real, live-rendered 3D wireframe (ported verbatim from `@card/wireframe-three`'s `mountCardArt`) of the aircraft's vendored `.glb` model (`public/aircraft-models/`, the same files the map's `ScenegraphLayer` uses), tinted to the rarity tier's color, rendered from a fixed camera angle with a ground-plane grid — not the flat 2D silhouette, except as an explicit fallback when the aircraft has no vendored model (matching the library's own fallback behavior).
- `PlaneCardProps` gains one new optional field, `showBack?: boolean` (default `true`); no other prop changes (`typeDesignator`, `category`, `manufacturerModel`, `rarityTier`, `cardStats` are untouched).
- New dependency: `three` (+ `@types/three`, dev), for `GLTFLoader`/wireframe rendering — this app's first use of `three.js` (the map's existing `.glb` pipeline uses `@loaders.gl/gltf` + deck.gl, a different, non-`three` object graph that the ported `mountCardArt` can't traverse).

## Capabilities

### Modified Capabilities

- `aircraft-info-overlay`: the "PlaneCard shows aircraft identity and rarity tier" and "PlaneCard shows optional fleet-wide stats when available, never fabricated" requirements are updated to describe the two-face flip card (back face shown by default via the `showBack` prop, front face on hover/flip) instead of a single static face, and to state the click-to-adsb.win-dashboard behavior explicitly (previously implied by implementation only, not spec'd). A new requirement describes the front face's 3D-model art and its flat-silhouette fallback.

## Impact

- `components/map/overlay/PlaneCard.tsx`: restructured to render `.aircraftRarityFrame > .cardInner > (.cardFace.cardFaceFront, .cardFace.cardFaceBack)`, moving the current identity/stat JSX onto the back face and adding new front-face JSX (pills, header, 3D-art mount slot, XP panel) ported from `@card/core`'s `aircraft-card.js`; adds the `showBack` prop (default `true`) driving `data-show-back`'s presence, and a `useEffect` that loads the aircraft's vendored `.glb` (if any) and mounts the 3D wireframe into the front face's art slot.
- `components/map/overlay/AircraftOverlay.tsx` (the only current view mounting `PlaneCard`): no code change required to get the new default (`showBack` defaults to `true`), but passes `showBack={true}` explicitly at this call site so the behavior is visible at the call site rather than relying silently on the prop's default.
- `components/map/overlay/PlaneCard.module.css`: card-frame/flip rules (perspective, `rotateY`, `backface-visibility`, per-face tier gradient border, `mythic`/`apex` sheen) ported from `@card/core`'s `card.css`, adapted to this app's CSS Modules class-naming convention; back-face-by-default achieved via `data-show-back`-driven hover/rest rules matching the library's own convention; new front-face-only rules (full-bleed art, legibility scrim, animated grid fallback, pills layout).
- `components/map/overlay/planeCardFrontArt.ts` (new): `collectMeshes`/`mountCardArt` ported verbatim from `@card/wireframe-three`, plus `loadAircraftGltfScene` (loads+caches the aircraft's vendored `.glb` via `three`'s own `GLTFLoader`).
- `components/map/aircraftModels.ts`: adds `resolveModelKeyForTypeAndCategory` (extracted from the existing `resolveModelKey`, which now delegates to it) and exports the existing `modelUrl`, so `planeCardFrontArt.ts` can resolve/fetch a vendored model from just a type designator/category, matching the map's own vendored-model resolution exactly.
- New dependency: `three` (runtime) + `@types/three` (dev) — see proposal's "What Changes" for why a second, `three`-native `.glb` parse is needed alongside the map's existing `@loaders.gl/gltf` pipeline.
- No changes to `aircraftModelCard.ts`, `tierProgress.ts`, `feederUuid.ts`, `manufacturerModel.ts`, or `aircraftShapes.ts`'s own logic (the front face reuses `aircraftShapes.ts`'s existing silhouette only as `mountCardArt`'s fallback markup) — this remains a presentation-layer change to `PlaneCard` (plus the two small, additive `aircraftModels.ts` exports).
