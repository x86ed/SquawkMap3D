## 2. CSS: flip frame and both faces

- [x] 2.1 `.aircraftRarityFrame` now holds only `--rarity-*` variables, `perspective`, `position: relative`, and sizing (`width: 320px; aspect-ratio: 5 / 7`) — no border/background/box-shadow of its own (those moved to the new shared `.cardFace`, task 2.4). All nine per-tier `--rarity-*` custom-property rules are untouched.
- [x] 2.2 `.cardInner`: `position: absolute; inset: 0; transform-style: preserve-3d; transition: transform`.
- [x] 2.3 Hover/rest rules ported verbatim (semantics corrected from an earlier pass — see below) to match `@card/core`'s own three rules exactly: `.aircraftRarityFrame:hover .cardInner{rotateY(180deg)}`, `.aircraftRarityFrame[data-show-back] .cardInner{rotateY(180deg)}`, `.aircraftRarityFrame[data-show-back]:hover .cardInner{rotateY(0deg)}`. `data-show-back` is now a boolean-*presence* attribute (`data-show-back={showBack || undefined}` in JSX), not a `"true"`/`"false"` string, matching the library's own convention.
- [x] 2.4 Added the shared `.cardFace` class (gradient border, `padding: 2px`, `box-shadow`, `backface-visibility: hidden`, `position: absolute; inset: 0`) applied to **both** `.cardFaceBack` and `.cardFaceFront` — each face is now a complete bordered card, so the whole card flips as one object. **This corrects a real bug found in manual verification**: an earlier version kept the border on the static outer `.aircraftRarityFrame` and flipped only the inner `.aircraftTierCard`, which visibly looked like content flipping *inside* a stationary frame rather than the card itself flipping.
- [x] 2.5 Front-face-only styles added: `.cardFrontContent` (dark background, own copy — not `.aircraftTierCard`, since the front face has no material-tier decoration in the library), its `::before` legibility scrim, `.cardFrontHeader`/`.cardFrontPills`/`.cardFrontIdentity`/`.cardFrontName`, `.cardFrontArt` (full-bleed 3D/flat-art mount slot), `.cardFrontGrid` (+ `card-grid-slide` keyframes, animated backdrop shown only in flat-fallback mode). `.cardBadgeRow` (renamed from an earlier shared/floating `.badgeRow`) is now back-face-only, in normal flow.
- [x] 2.6 `.cardInner { transition: none; }` added to the existing `prefers-reduced-motion: reduce` block; `.cardFrontGrid::before`'s animation also disabled there.
- [x] 2.7 (new) Fixed a real truncation bug found during manual verification: `.rarityBadge`/`.tierBadge` reused for the front face's `.cardFrontPills` inherited `max-width: calc(100%...)` + `text-overflow: ellipsis` from their back-face-row origin, which gave them a near-zero flex `min-width` against `.cardFrontIdentity`'s competing width, truncating "LEGENDARY"/"TITANIUM" to "LEG…"/"TITANI…". Fixed by unsetting `max-width`/`overflow`/`text-overflow` within `.cardFrontPills` (matching the library's own unconstrained `.card-pill`) and giving `.cardFrontPills` `flex-shrink: 0`.
