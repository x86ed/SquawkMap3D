## Why

`components/map/MapView.tsx`'s top-right control cluster (`.controls`, `MapView.module.css`) has grown to a flat vertical stack of ~20 buttons (theme, pilot mode, 15 individual layer toggles, follow-selected-aircraft, my-location, show/hide my-location) with no grouping, no search, and no way to browse the currently-tracked aircraft as a list — every inspection of a specific aircraft today requires clicking its icon on the map. This change replaces that flat stack with a right-hand slide-out drawer (styled/structured per the user-provided reference `/Users/adamsiegel/Downloads/adsb-drawer.html`): an accordion of grouped layer toggles, plus a searchable, filterable, sortable data table of every currently-tracked aircraft.

## What Changes

- Replace the top-right `.controls` button stack with two small always-visible controls in the same top-right corner: a day/night slider (defaulting to the OS `prefers-color-scheme`, same behavior as today's theme button — just a different affordance) and a button that opens/closes the new right-hand drawer. Pilot mode's toggle stays in this same top-right cluster as a third small control (unchanged behavior, just re-skinned alongside the slider).
- Add a right-hand slide-out drawer (`components/map/drawer/LayerDrawer.tsx`) containing, top to bottom: a small always-visible "view" row (Follow selected aircraft, My location — both pre-existing, just relocated), an accordion of layer-control groups, and the new plane-listing panel.
- Accordion groups and their rows, each row wired to the *existing* toggle handler already in `MapView.tsx` (no toggle logic changes — only where the button lives):
  - **Aviation**: Airports (`airportsVisible`), OpenAIP TMS (`openAipVisible`), TFRs (`tfrVisible`), Special Use Airspace (`suaVisible`), Airspace Boundaries (`airspaceBoundariesVisible`), plus this app's two existing aviation-adjacent layers not named in the reference mock but with no other logical home: Military Bases (`militaryVisible`) and Aircraft (`aircraftVisible`, the on-map aircraft icons).
  - **Location**: Transponder Location (renamed-in-UI-only from today's "my location" marker toggle, `userLocationVisible`), Actual Range Outline (`rangeOutlineVisible`), Terrain-Based Range Outline (`terrainOutlineVisible`), and a **new, independent** Range Rings toggle — **BREAKING** (behavior, not API): today `setUserLocationVisibility` shows/hides the satellite marker and the 4 range rings together as one switch; this change splits that into two switches per the acceptance criteria's explicit "must be separated from transponder location layer."
  - **Environmental**: a nested "Weather" row that expands to this app's 5 already-independent weather layers (RainViewer, NEXRAD, NOAA Radar, DWD RADOLAN, NOAA Infrared — each keeps its own existing independent toggle/spec, unmodified), Day/Night Terminator (`terminatorVisible`), and a disabled "Wildfires (soon)" placeholder row with no backing layer, matching the reference mock's own disabled "soon" row.
- Add a plane-listing panel (`components/map/drawer/PlaneListingPanel.tsx`) below the accordion: a tab nav (Search / Filters / Columns) over a sortable data table of every currently-tracked aircraft, columns: Hex ID, Flag, Callsign, Airline, Route, Registration, Type, Squawk, Altitude, Speed, Vertical Rate, Distance, Track, Messages, Seen, RSSI, Latitude, Longitude, Source, Mil., Wind D., Wind S., XP, Rarity, Registrations, Flight Time, Level. Column headers sort ascending/descending on click, matching the reference mock.
- Extend `components/map/aircraft.ts`'s `Aircraft` interface and `normalize()` with fields readsb's `aircraft.json` already exposes but this app never parsed: `messages` (message count), `rssi`, `sourceType` (raw `type`, e.g. `adsb_icao`/`mlat`/`tisb`), `isMilitary` (derived from `dbFlags` bit 0x1), `windDirection`/`windSpeed` (`wd`/`ws`, rarely populated).
- Add small new lookup modules: `components/map/registrationCountry.ts` (tail-number-prefix → ISO country code, reusing `airportPopup.ts`'s existing `flagSvgPathForCountryCode` for the Flag column) and a vendored `components/map/data/airlineDesignators.json` (ICAO 3-letter callsign prefix → airline name, for the Airline column).
- XP, Rarity, Registrations (count), and Flight Time have no backing computation anywhere in this codebase today beyond `aircraftRarity.ts`'s existing rarity tier/value. Per this change's scope (a UI container, not a new gamification system): Rarity renders the real, already-computed tier/value from `aircraftRarity.ts`; XP, Registrations, and Flight Time are **stubbed for now** — rendered as a placeholder (`—`) column, hidden from the default column set — the same "present now, real data soon" treatment the acceptance criteria itself gives the Wildfires row, not a permanent non-goal. A follow-up change is expected to wire up real per-hex tracking (XP/Registrations/Flight Time) once that system exists; this change only reserves the column/UI slot for it.
- Airline/Route lookups reuse the *exact same* per-aircraft caching this app already does for the selected-aircraft overlay (`MapView.tsx`'s existing `routeCacheRef`, keyed `${hex}:${callsign}`) — extracted into a shared `getCachedFlightRoute()` in `flightRoute.ts` so both consumers hit one cache. No new rate-limiting, debouncing, or request-staggering is introduced beyond that existing dedupe-by-identity behavior — the plane listing panel's route lookups are not throttled any more than the app already throttles this today.

## Capabilities

### New Capabilities
- `layer-control-drawer`: the right-hand slide-out drawer shell, the top-right day/night slider + drawer-toggle button, and the accordion of grouped layer-control toggles (Aviation, Location, Environmental) that replaces the flat `.controls` button stack.
- `plane-listing-panel`: the drawer's tabbed search/filter/column-configuration UI and sortable data table of currently-tracked aircraft.

### Modified Capabilities
- `user-location-marker`: splits the existing single "toggle to hide/show user location marker and range rings together" requirement into two independently-toggleable controls (marker/transponder-location vs. range rings).

## Impact

- `components/map/MapView.tsx`: removes the `.controls` button-stack JSX; adds `drawerOpen` state, `rangeRingsVisible` state (separate from `userLocationVisible`), a `siteLocation` state mirroring `userLocationRef.current` (for the plane-listing table's Distance column); mounts `<LayerDrawer>` and passes it every existing toggle state/handler plus the new ones.
- `components/map/userLocation.ts`: `setUserLocationVisibility` (marker+rings together) splits into `setUserLocationMarkerVisibility` and `setRangeRingsVisibility`, each independently setting `USER_LOCATION_ICON_LAYER_ID` vs. `USER_RINGS_LINE_LAYER_ID`/`USER_RINGS_LABEL_LAYER_ID`.
- `components/map/MapView.module.css`: `.controls` shrinks to the 3-item top-right cluster (slider, pilot mode, drawer toggle); the removed per-layer button styles move to the new drawer's own CSS modules.
- New: `components/map/drawer/` (`LayerDrawer.tsx`, `ThemeSlider.tsx`, `Accordion.tsx`, `PlaneListingPanel.tsx`, `PlaneTable.tsx`, `columns.ts`, `aircraftDisplay.ts`, plus a `.module.css` per component).
- New: `components/map/registrationCountry.ts`, `components/map/data/airlineDesignators.json`.
- `components/map/aircraft.ts`: extends `Aircraft`/`RawAircraftJson`/`normalize()` with `messages`, `rssi`, `sourceType`, `isMilitary`, `windDirection`, `windSpeed`.
- `components/map/flightRoute.ts`: adds `getCachedFlightRoute(hex, callsign, lat, lon)` (wraps `getFlightRoute()` with the same `${hex}:${callsign}`-keyed cache `MapView.tsx` already manages locally today) and `clearFlightRouteCache()`; `MapView.tsx`'s existing `routeCacheRef` logic is replaced with calls to these, so the aircraft overlay and the new plane-listing panel share one cache and neither adds throttling beyond what exists today.
- No new npm dependencies — drawer, accordion, tabs, and table are hand-rolled React + CSS Modules, matching every existing component in `components/map/overlay/` and `components/map/controls/` (no UI kit is installed or introduced).
- No changes to any layer's rendering logic, refresh intervals, or MapLibre/deck.gl setup — this change only relocates existing toggle *controls* and adds a new *read-only* listing view on top of aircraft data this app already polls.
